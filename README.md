# 风险模型命中反馈治理

界定监管线索、核查结果和模型反馈标签的关系，并提供命中反馈治理后台的可验证参考实现。

## 领域资料

仓库中的 `contracts/` 描述各实体的 JSON Schema 契约，`fixtures/` 给出可公开使用的
虚构样例，`src/` 为纯标准库实现的治理逻辑，`tests/` 为校验用例。业务服务可沿用相同
标识和版本约定。

当前资料反映的事实包括：

- 全国排查下发近两百万条核查线索
- 线索需要地方核查后才能形成结论
- “未立案”混杂证据暂缺、合法例外、数据错误与尚未完成，不能一律作为负样本
- 反馈质量会影响后续风险识别

## 治理闭环

1. **线索反馈**：每条线索保存触发规则/模型版本、输入数据水位、分派范围、核查阶段与
   结构化结论（`contracts/lead.schema.json`）。
2. **权限签发**：标签只能由辖区内、在职的高级复核者在证据充分时签发；调查结论不能
   自行升级为稳定标签（`src/reviewers.py`、`src/labels.py`）。
3. **版本流转**：申诉或后续案件结果以新版本追加，旧版本置为 superseded；签发错误可
   撤销，历史不被覆盖。
4. **训练快照**：仅输出脱敏快照（加盐假名、区域分桶、时间取整），按标签稳定时间做
   train/validation/test 切分；未结案、证据暂缺、跨区域重复、规则自证、冷静期未满、
   撤销标签等一律排除并记录原因码（`src/snapshot.py`）。
5. **批次说明**：模型负责人可逐码说明某批反馈为何可用、哪些被排除
   （`src/batch_report.py`）。
6. **上线监控**：追踪新版本上线前后命中分布与人工负担变化（`src/monitoring.py`）。
7. **审计追溯**：任一指标可沿 lead_id → 标签版本 → 证据登记号 → 签发人回溯
   （`src/audit.py`）。

完整设计见 [`docs/DESIGN.md`](docs/DESIGN.md)。
