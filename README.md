# 风险模型命中反馈治理

界定监管线索、核查结果和模型反馈标签的关系。

## 领域资料

仓库中的 `contracts/context.schema.json` 描述基础资料格式，`fixtures/context.json` 给出可公开使用的示例。代码库只负责读取与校验这些资料，业务服务可沿用相同标识和版本约定。

当前资料反映的事实包括：

- 全国排查下发近两百万条核查线索
- 线索需要地方核查后才能形成结论
- 反馈质量会影响后续风险识别

## 核心模块

- `src/leads.py` — 线索台账：触发规则/模型版本、输入数据水位、分派范围、核查阶段与结构化结论。“未立案”区分为证据暂缺、合法例外、数据错误、尚未完成，不能一概当作负样本。
- `src/labels.py` — 标签签发：仅持有签发角色且被授权到线索所在区域的复核者，在结案且证据充分时才能签发；申诉与后续案件结果形成新的不可变版本，历史完整保留。
- `src/snapshots.py` — 训练用脱敏快照：加盐哈希去除原始标识，按明确时间切分划分训练/验证集；尚未结案、跨区域重复、规则自证、数据错误、未签发、超出切分的记录逐条登记排除原因。
- `src/metrics.py` — 版本上线后的命中分布与人工负担（单条命中平均工时、在办量），每个指标行保留贡献者引用。
- `src/governance.py` — 批次治理报告：说明某批反馈为何可用、哪些被排除，比较新旧规则版本的命中量/阳性率/人工负担变化，并支持审计从指标回溯到具体签发依据。

## 本地校验

运行项目自带测试即可确认样例资料可读取，且领域标识与版本字段完整。所有示例均为虚构数据，不含真实个人信息、账号或访问凭据。
